# Patternhaus v0.2.0-m2: Milestone 2, Make a Song (draft release notes)

**Status: draft, not tagged.** Tagging `v0.2.0-m2` needs the owner's explicit OK after the
sign-off items in [`docs/milestones/M2.md`](../milestones/M2.md#owner-sign-off-items).
`release.yml` builds the notes from the tag's section of `CHANGELOG.md`, so before tagging,
copy the section below (from "Second milestone release") into `CHANGELOG.md` under a
`## [v0.2.0-m2] - Milestone 2: Make a Song` heading, folding in what is under "Unreleased".

---

Second milestone release, pre-alpha. A person in the UI, or an agent through MCP alone, can
make a full song: arrange sections with automation, use audio loops that follow the tempo,
record and edit audio, slice loops into instruments, play CLAP and VST3 plugins next to the
built-ins from a MIDI keyboard, and bring in an FL Studio project to keep working on it.

### Added

- **Audio clips in the playlist:** drag audio in from Explorer or the browser; trim either
  edge, slip, split, duplicate; fade-in and fade-out handles with four curve shapes; gain,
  reverse, pitch in semitones and cents; waveforms drawn and cached per zoom level. Long files
  stream from disk.
- **Tempo:** per-sample BPM, detected from onsets and editable; three stretch modes per clip
  (Resample, Stretch with Signalsmith Stretch (MIT), Slice at transients); Fit to tempo in one
  step; tempo-synced clips follow tempo automation.
- **Audio editor and slicer:** an Edison-style editor (select, cut, copy, paste, trim,
  normalise, fades, reverse, silence, gain, de-click) that never overwrites a file and undoes
  in one step; transient detection with a sensitivity setting, markers you can move, and a
  sliced Sampler instrument with a pattern that replays the loop.
- **Automation:** automation clips on any instrument, effect, plugin, mixer, channel, send or
  tempo parameter, with linear, hold, smooth and S-curve points; "Create automation clip" from
  any knob; recording automation from knob moves; sample-accurate in the engine.
- **Recording:** arm an input for a track or a Sampler channel, monitor through the mixer
  with a latency readout, count-in and punch over the loop region; every take is a new WAV in
  `samples/` with latency compensation that keeps the whole file.
- **MIDI:** a MIDI keyboard plays the selected channel (hot-plug), with mod wheel, pitch bend
  and pressure; record notes into a pattern; MIDI learn on any knob, saved per user.
- **Plugins:** CLAP and VST3 instruments and effects in-process, a scanner with a cache and a
  blocklist (each file scanned in a helper process), plugin editors embedded on Windows and
  floating elsewhere, a generic parameter view, state saved with the project, and a crash
  guard that silences a crashing plugin and marks it *isolate* while the session keeps
  running. `patternhaus-cli plugin-scan --report` writes a compatibility report.
- **Effects:** multiband compressor, gate/expander, convolution reverb with generated impulse
  responses, chorus, flanger, phaser, bitcrusher, stereo tools, and a spectrum / loudness /
  phase analyser whose window shows its own slot.
- **FL Studio import:** open a `.flp` (or drop it) as a new Patternhaus project with an import
  report: channels, patterns and notes, the playlist (pattern, audio and automation clips),
  mixer routing and levels, tempo; native FL plugins map to built-ins or labelled placeholders
  that keep their data. Written clean-room from a public-facts spec (`docs/formats/flp.md`).
- **Agents:** every M2 command is reachable over MCP, JSON-RPC and the CLI, with M2 tools for
  audio clips, fit to tempo, automation and plugins; `render { listen: true }` returns a short
  WAV excerpt; reference-track comparison (`analyze { what: ["reference"] }`); agent preview
  mode, where a batch shows as ghost notes and clips you accept or reject.
- **UI:** CJK names render with the system's CJK fonts; new channels and patterns take theme
  colours clear of the agent colour; finer grid lines are easier to see; `ph-app.exe` carries
  its icon.

### Changed

- Project format 2 (audio clips, automation clips, the sample registry); format 1 projects
  load unchanged.
- `file.import_flp` places imports in `Documents\Patternhaus Projects\<name>` by default, or
  next to the FL project on request.

### Fixed

- Agent renders (`render`, `analyze`, `snapshot`) now include plugin instruments and effects;
  they rendered silent there before.

### Quality

- The M2 acceptance test builds a 32-bar song through MCP only (intro, build and drop, a
  filter sweep and a volume ride, a loop fitted to tempo, a slice instrument, the test CLAP
  plugin, a multiband compressor and a convolution reverb): the export is bit-identical to the
  offline render, -11.95 LUFS, -1.01 dBTP.
- Live playback is bit-identical to the offline render with audio clips, automation, the test
  plugins and an armed recording input, with no allocation on the audio thread.
- 10.97% mean DSP load for the reference project plus 8 stretched clips and 4 automation clips
  (48 kHz, 256 frames, all cores, Ryzen 7 7800X3D), against a 25% target.

### Known limitations

- Warp markers are not in M2. WASAPI exclusive mode is not available (the ASIO build covers
  exclusive access). macOS VST3 bundle loading and plugin editors on macOS and Linux are not
  done; out-of-process plugin isolation is M4.
- CJK text needs CJK fonts installed on the system (no CJK font is bundled).
- Recording inputs must run at the engine's sample rate; MIDI mappings follow project object
  ids.
- Agent proposals are not saved with the project; ghosts are drawn for notes and clips only.

Builds are MIT OR Apache-2.0. An archive marked asio-gpl3, if present, is the GPLv3 ASIO build.
